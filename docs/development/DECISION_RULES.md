# Decision Rules

## 1. Purpose
本ドキュメント（`DECISION_RULES.md`）は、Builderが作業を自律的に進行する際の「自律判断領域」と「人間判断のために停止・相談すべき境界」を明確化する開発ルールです。

## 2. Human Decision Required (停止条件)
以下の条件に該当する場合、Builderは作業を一時停止し、人間に判断を提示して指示を仰ぎます。

- **仕様・要件の重大な曖昧性**: Product要求が複数解釈でき、選択によりユーザー体験や仕様が大きく変わる場合
- **SSOT間の重大な矛盾**: 各ドキュメント・規則間に矛盾があり、優先順位ルールだけでは解決できない場合
- **不可逆・外部影響操作**: 本番公開・パッケージ配布・課金発生・外部API送信・不可逆なデータ破棄等を伴う場合
- **権限・契約・法務判断**: 人間しか保持しない資格情報、アカウント権限、ライセンス・契約・権利に関する判断が必要な場合
- **Task Scopeの拡大・変更**: Taskの本来の目的や範囲を大きく変更する必要が生じた場合

## 3. Builder Decision (自律進行領域)
以下の作業・判断については、途中確認を行わずBuilderが自律的に決定・実行します。

- ディレクトリ構造・ファイル構成の軽微な調整
- 関数名・変数名・クラス名等の内部命名
- 内部実装パターンおよびロジック構成
- テストケースの追加および検証手順の選定
- 一般的なビルドエラー・リンターエラー・構文エラーの修正
- Task達成に必要な小規模なコードリファクタリング
- ドキュメントのフォーマット整形・リンク修正・typo修正
- 既存の実装パターンや既存規約に沿った設計判断

## 4. Blocking Behavior (停止時の必須動作)
人間判断が必要と判断して作業を停止（BLOCK）する場合、Builderは以下を明確に提示して停止しなければなりません。

1. **判断不能な事項**: 何が決まらないのか
2. **選択肢の提示**: 実行可能な選択肢（案A, 案Bなど）
3. **各選択肢の影響**: メリット・リスク・影響範囲
4. **Builder推奨案**: 合理的に提案できる場合の推奨理由
5. **完了済み安全範囲**: 現在の時点で安全に完了・検証できている作業範囲
